# 聊天室功能设计文档

## 概述

设计一个多人协作聊天室，允许多个 AI 模型在一个房间里协作完成任务。每个模型有预设的角色身份，可以讨论、执行和 Review。

## 核心概念

```
项目 (Project)
  └── 聊天室 (ChatRoom)
        ├── 角色配置 (Role + Model)
        ├── 讨论阶段 (Discussion)
        ├── 执行阶段 (Execution)
        └── Review 阶段 (Review)
```

## 用户场景

### 典型流程

```
用户: "帮我重构这段代码"

[讨论阶段]
架构师: 建议用简单工厂模式
程序员: 同意，这样更简单
用户: 我也同意
→ 达成共识

[执行阶段]
程序员: 正在实现...
架构师: 建议加个缓存
程序员: 好的

[Review 阶段]
测试员: 发现一个边界情况没处理
程序员: 已修复
测试员: LGTM ✅
```

## 功能清单

### 1. 聊天室管理

| 功能 | 说明 |
|------|------|
| 创建聊天室 | 用户输入名称、描述、选择角色 |
| 删除聊天室 | 需要确认 |
| 编辑聊天室 | 修改名称、描述、角色配置 |
| 列表展示 | 显示所有聊天室 |

### 2. 角色配置

#### 预设角色

| 角色 | 职责 | 推荐模型 |
|------|------|----------|
| 架构师 | 系统设计、方案决策 | Claude Opus |
| 程序员 | 代码实现 | GPT-4o / Claude Sonnet |
| 测试员 | 代码审查、找bug | Gemini Pro |
| 产品经理 | 需求分析、用户体验 | Claude Sonnet |

#### 角色属性

```swift
struct ChatRoomRole: Codable, Identifiable {
    var id: String              // 角色 ID
    var name: String            // 角色名称（如"架构师"）
    var description: String     // 角色职责描述
    var systemPrompt: String    // 系统提示词
    var icon: String            // SF Symbols 图标
    var modelID: String?        // 关联的模型 ID（可选）
}
```

#### 模型选择

- 每个角色可以选不同的模型
- 对话开始前指定
- 对话过程中不可更改

### 3. 发言模式

#### 轮流发言（默认）

```
架构师 → 程序员 → 测试员 → 产品经理 → 架构师 → ...
```

#### 用户指定

- 用户可以 @某个角色，指定下一个发言者
- 用户可以随时插话，所有模型都能看到

### 4. 用户介入方式

| 方式 | 说明 |
|------|------|
| 插话 | 用户随时发消息，所有模型可见 |
| 指定发言人 | 用户说"@程序员 你来实现" |
| 投票 | 用户投票支持某个方案 |
| 终止讨论 | 用户手动结束讨论阶段 |

### 5. 讨论阶段

#### 流程

1. 用户提出问题
2. 模型轮流讨论
3. 用户可以插话、指定发言人
4. 达成共识或用户指定方案 → 进入执行阶段

#### 终止条件

- **自动检测共识**：所有模型都同意某个方案
- **用户指定**：用户说"用方案B"
- **手动停止**：用户点击"停止讨论"

#### 共识检测

```swift
// 简单实现：检测关键词
func detectConsensus(messages: [Message]) -> Bool {
    // 检测 "同意"、"我也同意"、"LGTM" 等关键词
    // 或者用户明确说"用方案X"
}
```

### 6. 执行阶段

#### 流程

1. 被指定的模型开始执行（通常是程序员）
2. 其他模型可以提建议
3. 执行完成 → 进入 Review 阶段

#### 代码执行（可选）

- 用户可以决定是否执行代码
- 执行结果反馈给所有模型

### 7. Review 阶段

#### 流程

1. 测试员（或其他角色）审查代码
2. 发现问题 → 回到执行阶段
3. 审查通过 → 完成

#### Review 结果

```swift
enum ReviewResult {
    case approved        // 通过
    case needsChanges    // 需要修改
    case rejected        // 拒绝
}
```

### 9. 上下文管理

- 共享上下文：所有模型看到完整对话历史
- 让每个模型自己处理长上下文（不做摘要）

### 10. 存储

使用 Project 模式：

```
~/.new-pi/projects/
  └── {project-id}/
        ├── project.json          # 项目配置
        └── chatrooms/
              └── {chatroom-id}/
                    ├── chatroom.json   # 聊天室配置
                    └── messages.jsonl  # 对话记录
```

## 数据结构

### ChatRoom

```swift
struct ChatRoom: Codable, Identifiable {
    var id: String
    var name: String
    var description: String
    var roles: [ChatRoomRole]
    var createdAt: Date
    var updatedAt: Date
}
```

### ChatRoomMessage

```swift
struct ChatRoomMessage: Codable, Identifiable {
    var id: String
    var chatroomID: String
    var roleID: String          // 角色 ID（或 "user"）
    var content: String
    var phase: Phase            // 讨论/执行/Review
    var timestamp: Date
}

enum Phase: String, Codable {
    case discussion
    case execution
    case review
}
```

### ChatRoomProject

```swift
struct ChatRoomProject: Codable, Identifiable {
    var id: String
    var name: String
    var description: String
    var chatrooms: [String]     // 关联的聊天室 ID
    var createdAt: Date
}
```
