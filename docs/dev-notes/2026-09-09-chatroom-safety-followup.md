# 合并后的聊天室安全与导航收尾

## 合并基线

基于 `71d2a4d`，保留已合入的外观模式、项目根内文件操作免审批、Xcode ID 冲突修复和运行中禁止删除聊天室。

## 行为约定

- 聊天室工作目录由用户选择，与 Session 当前项目独立。
- 删除保护沿用 `71d2a4d`：任务刚创建、运行中、待审批、取消尚未完成均拒绝删除，错误可见。
- 目录检查只读，区分无效/相对路径、目录丢失、路径实际是文件及无权限。
- 创建、打开详情、App 重新激活以及两种发言入口均检查目录；发言 Task 执行前再检查一次，并先检查 Task 取消。
- 失效目录不会删除历史。侧边栏警告、详情显示完整路径；禁止推进/@指定发言，恢复原目录后可“重新检查”。
- 本轮不提供已有聊天室迁移到其他目录的功能，以免旧项目对话驱动新项目工具操作。也不把 Session 换项目等同于聊天室目录失效。
- 不主动中断已经运行的工具；本轮目录检查不是文件系统实时监控，也不是替代工具层路径/审批防护。
- 侧边栏按规范化完整路径分组，分组默认展开、可以折叠，组内保留最近更新时间排序；不同位置同名目录不合并。创建新聊天室时展开其分组。
- Spike 菜单、Window scene、通知入口、autorun 和实验 Swift 源码仅在 Debug 编译。Release 保留 API 监控。

## 验证

- Swift Package：271 tests / 77 suites 通过，包含 6 个新增目录测试。
- App 层检查脚本：`scripts/validation/check-chatroom-controller.sh`。
  - 使用真实 `ChatRoomFlowController` / `ChatRoomRuntimeStore`，仅将无关转录适配器替换为空实现。
  - 检查运行中、取消待退出、待审批时删除保护，两种发言入口的目录失效拦截及恢复。
  - 随机聊天室 ID、无配置角色；不请求模型、不操作工具、不写已有对话。
- Debug / Release 构建通过；二进制检查确认 Spike 标题、通知名、autorun 环境变量仅存在于 Debug，不存在于 Release。
- 原生 Accessibility 实测：无 Session 项目时仍显示全部聊天室，按 `new-pi` / `tab-helper` 分组；折叠一组不影响另一组，重新展开恢复行。

## 尚未覆盖

- 已运行工具期间目录被移动的中断/恢复语义。
- 真实外置磁盘热拔插、网络卷异常；目录失效/恢复已有临时目录测试。
- 已有聊天室迁移到不同项目，需要单独明确需求。
